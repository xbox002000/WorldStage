# 給下一位接手者的話

寫於 2026-10-03，額度用完之前。先讀 `docs/HANDOFF.md`（規則、地圖、指令），再讀這一頁（方向）。

## 我們走到哪裡
世界會自己過日子，角色有內心，LLM 角色會開口、會說謊、會心口不一；編劇能從世界裡找出一集，劇本檢查是 0 個問題；導播室與角色工坊都能用。
**但我們還沒有拍過一秒真正的影片。** 到目前為止，「影片」只是鏡頭單（ProductionPacket）和 dry-run。這是最大的缺口，也是這個專案存在的理由。

## 真正的目標
不是「AI 寫故事」，而是：**一個真的發生過的世界，被剪成觀眾想看的影片。** 因果是真的，所以戲是掙來的。請守住這一點：任何捷徑（叫 LLM 直接編劇情、為了好看改世界）都會毀掉它。

## 接下來的路（依序）
1. **先拍出第一支 30 秒短片，品質不重要，管線要通。**
   - 從導播室的一集（例如 `soul-drama701v3b` 某一天）→ 鏡頭單 → 資產冊（`production/bible.py`）→ 一個真的影片 provider。
   - 不花錢的路：3D 觀測台已能錄（three.js＋無頭 Chrome），先把一集錄成影片，配上台詞字幕與 TTS（Gemini TTS 免費，見記憶檔）。這就是「動態分鏡」，能讓使用者第一次看到成品。
   - 付費模型要先問使用者並估價；新模型一律先過 `tests/provider_conformance/`。
2. **角色要長一樣。** 資產冊的參考圖欄位還是空的：用免費或本機方法給每個角色一張定裝圖，之後所有鏡頭都參照它（臉、服裝、身形）。沒有一致性，影片就不成立。
3. **聲音。** 每個角色一個固定聲線（Genome 的 voice 欄位已在），台詞＋心聲（旁白）分開處理。
4. **讓使用者評分。** 每一集讓使用者打分，存下來；之後所有「好不好看」的改動都對照這個分數，不要只看我們自己的量尺。
5. **劇情的深度（還沒做的）：** 好人卡變成故事、恩情與欠債、家與責任、秘密當籌碼（見計畫 v0.8 的 E 段）；集現在偏薄（每集約 3 場），要使用者看過再決定方向。

## 我學到的事（請別重蹈覆轍）
- **先量再做。** 這個專案好幾次「直覺的改法」量了才發現是錯的（例如把 LLM 的理由全當台詞，只有 9% 是對人說的）。
- **說實話。** 沒成立的照寫；文件裡每個數字都要能重跑出來。使用者重視這點勝過漂亮的數字。
- **舊世界不能變。** 新機制一律是新配方；改任何會進入 LLM 提示的文字，已記錄的世界就要補錄。
- **分工省額度。** 我寫清楚的任務說明（含紅線與驗收指令），交給 Grok Build 實作（`grok -p ... --cwd <worktree>`），我只驗收。給它獨立 worktree、禁止 commit／push／刪檔／junction。

這條路還很長，但地基是穩的。祝你拍出第一支片。
